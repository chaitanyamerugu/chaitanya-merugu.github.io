Component 1

Layers — stages of transformation

A layer is a group of neurons that processes data at the same stage. Each layer receives the previous layer’s output and produces a new, more useful representation of it.

Input layer

Receives the raw features

One neuron per feature, such as pixel values, sensor readings, or the X₁ and X₂ coordinates in TensorFlow Playground. It performs no computation; it simply passes values forward.

Hidden layers

Learn intermediate patterns

Early layers detect simple patterns (edges, straight boundaries); deeper layers combine them into complex ones (shapes, curves, spirals). More layers mean depth; more neurons per layer mean width.

Output layer

Produces the prediction

Its size and activation match the task: one neuron for a regression value, one sigmoid neuron for yes/no, or one softmax neuron per class for multi-class problems.

Component 2

Neurons — the basic unit

One neuron: weigh the inputs, add them up, apply an activation.

What a neuron does

Each neuron multiplies every incoming value by a weight, adds them together with a bias, and passes the total through an activation function. The result is a single number, its activation.

Why it matters

One neuron can only draw a simple boundary. In Playground, every neuron’s thumbnail shows the region it responds to. Combining many neurons across layers is what lets the network outline curved or irregular shapes.

Component 3

Weights & biases — what the network learns

Weights: connection strength

Every connection between two neurons carries a weight. A large positive weight strongly amplifies a signal; a negative weight suppresses it; a weight near zero effectively ignores it.

Biases: the starting point

Each neuron also has a bias. It shifts the neuron’s threshold so the neuron can still produce output even when its inputs are zero. Without biases, every decision boundary would have to pass through the origin.

Learning = adjusting weights

Weights begin as small random numbers. Training adjusts every weight in the direction that reduces the loss. The knowledge of a trained network lives entirely in its weights and biases.

w_new = w_old − learning_rate × ∂Loss/∂w
Playground uses the same convention: blue = positive, orange = negative, thicker = stronger.
Component 4

Activation functions — adding non-linearity

Without activation functions, stacking layers would still produce a single straight-line model. A non-linear activation lets the network bend its decision boundaries to fit real-world data.

ReLU

max(0, z)

The default for hidden layers. Fast to compute and avoids vanishing gradients for positive inputs.

Sigmoid

1 / (1 + e⁻ᶻ)

Squashes output into 0–1, so it is ideal for an output neuron that gives a probability for yes/no.

Tanh

tanh(z)

Output from −1 to 1 and centered on zero. Playground’s default, and it often trains smoothly on small networks.

Linear

z

No transformation. Used at the output for regression; in hidden layers it cannot solve curved problems.

Component 5

Loss functions — measuring error

What a loss function does

It converts “how wrong was the prediction?” into a single number. Lower is better. The whole goal of training is to make this number as small as possible on data the network has never seen.

Regression

Mean squared error (MSE)

Averages the squared difference between predicted and actual values. Large mistakes are penalized heavily.

MSE = mean((y − ŷ)²)
Classification

Cross-entropy

Penalizes confident wrong answers most heavily. It is the standard loss for predicting classes such as spam/not spam or cat/dog.

L = −Σ y · log(ŷ)

Component 6

Optimization algorithms — finding better weights

Good learning rateToo high: overshoots
The loss landscape seen from above. The optimizer walks downhill toward the lowest point.

Gradient descent

Backpropagation computes the gradient, the slope of the loss for each weight. The optimizer then steps every weight downhill. The learning rate sets the step size.

Stochastic & mini-batch (SGD)

Instead of using the full dataset per step, it estimates the gradient from a small batch. Each step is noisier, but training is far faster. Playground’s batch size slider controls this.

Adam & adaptive methods

Adam keeps momentum and gives each weight its own adaptive step size, so it converges quickly with little tuning. It is the most common default in practice.

One full pass through the training data. Playground’s counter in the top-left shows how many have run.

Hyperparameters

Settings chosen by the designer, not learned: learning rate, layers, neurons, activation, batch size, regularization.

Generalization

The real goal is low loss on unseen test data, not just memorizing the training set.

Hands-on · TensorFlow Neural Network Playground

What experimenting revealed

Data type

Simple data needs a simple network

The Gaussian clusters can be separated by a straight line, so even zero hidden layers worked. The circle and XOR sets needed at least one hidden layer with a non-linear activation. The spiral was the hardest and needed more layers and neurons, or extra features like sin(X).

Noise

Noise blurs the boundary

Raising noise made the classes overlap. Test loss stayed noticeably higher than training loss, and large networks began to fit the noise itself, which is overfitting.

Features

Better features, smaller network

Adding engineered features like X₁², X₂² let a tiny network solve the circle almost instantly. The network had less to learn on its own.

Layers & neurons

Capacity vs. training time

Adding layers and neurons let the model draw more complex shapes, but each epoch took longer and the loss curve became less stable. A learning rate that was too high made the loss jump instead of fall.

Summary

Why visualizing neural networks matters

Importance of visualization
  • Turns a black box into a glass box. Seeing weights, neuron outputs, and decision boundaries shows why a model behaves the way it does.
  • Speeds up diagnosis. Loss curves expose overfitting, underfitting, and bad learning rates at a glance.
  • Bridges technical and business audiences. A diagram explains a model to stakeholders far faster than equations can.
  • Builds trust. Explainable models are easier to validate, govern, and adopt responsibly in enterprise systems.
01

Every component has one job. Layers structure, neurons compute, weights store knowledge, activations add curvature, loss measures error, and optimizers improve.

02

Bigger is not always better. The right features and a right-sized network beat brute-force depth.

03

Watch the test loss. Generalization to unseen data is the real measure of success.

04

Hyperparameters are design decisions. Learning rate, activation, and architecture choices shape both training speed and accuracy.
